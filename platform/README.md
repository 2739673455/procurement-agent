# 采购业务平台

本目录用于建设独立部署的业务后端，使用 Python + FastAPI，采用模块化单体架构。

包含四个业务模块：

- 采购管理：采购申请、寻源、协议合同、订单、履约与变更。
- 供应商管理：供应商档案、准入与绩效。
- 财务管理：采购预算、发票与应付、付款申请及实付登记。
- 库存与仓储：库存流水、收货与退货。

用户、组织、权限、审批协调和业务审计由业务后端统一管理。Agent 服务独立部署，通过受控业务 API 调用本系统，不直接访问业务数据库。

平台面向多公司、多币种采购，覆盖实物、服务、软件许可及订阅等采购类型。业务单据按所属公司管理权限、审批和预算，记录交易币种及必要的汇率信息；实物采购通过收货入库确认履约，服务、软件许可及订阅等采购通过成果、交付或服务期间验收确认履约，不要求全部进入库存。预算执行口径及已付款退货等规则按各公司制度确定。

## 采购前置条件

公司与组织、人员权限、审批规则、采购类别、供应商档案、币种与汇率配置、预算等由对应管理人员建立并持续维护；涉及实物采购时，还需维护物料、仓库和期初库存。这些属于平台基础管理，不是每次采购都要重复执行的步骤。

单次采购只检查所需配置和数据是否可用。发现缺项时，由责任人补充；新供应商准入、预算调整等可作为本次采购触发的配套流程，完成后再推进受影响的业务环节。

## 采购流程总览

流程以 IBM TRIRIGA 11.6 的采购生命周期为参考，并按本项目的四模块边界、多公司、多币种和非实物采购要求调整。参考来源、业务对象、状态及配套动作见[采购流程与业务动作设计](docs/PROCUREMENT.md)。

主线是提出需求、申请审批、分配采购任务、核实需求、确定采购方式、形成采购承诺、履约验收、发票核对、付款申请、实际付款及收尾。采购方式有以下分支：

- **协议下单**：已有适用的框架采购协议或服务协议，直接引用协议准备订单，跳过本次竞争寻源。
- **RFQ 询价**：先发询价，再接收报价，经比价和审批形成订单。
- **RFP 方案征集**：先征集方案与报价，再综合评审，按批准结果准备订单或合同。
- **招标**：发布招标文件、接收投标、评标及授予，通常进入合同订立。

询价与报价是两个阶段，招标与投标也分别由采购方和供应商执行。直接采购或单一来源须符合公司规则及例外审批，不允许通过伪造报价凑足家数。

以下每一行只指定一个执行角色和一个业务动作。“平台”表示业务后端自动执行；供应商首期在线下参与，由内部人员登记凭证。阶段编号表示阅读顺序，只有适用分支才执行；分批交付、开票、付款可以交错进行。审批与签署、批准付款与实际支付均分别记录。

## 逐步执行流程

### 1. 提交采购申请

| 步骤 | 执行角色 | 动作             | 结果或执行条件                                                                 |
| ---- | -------- | ---------------- | ------------------------------------------------------------------------------ |
| 1    | 申请人   | 选择采购所属公司 | 仅可选择获授权公司；只有一个可选公司时默认带出。                               |
| 2    | 申请人   | 填写采购申请     | 记录类型、类别、用途、数量或服务范围、交付要求、预计金额、币种和费用承担部门；可填写建议采购员（由系统校验，供分配参考，通常不直接决定任务归属）。 |
| 3    | 申请人   | 提交采购申请     | 一张申请只属于一家公司；混合类型按明细记录。                                   |
| 4    | 平台     | 校验申请完整性   | 非实物无需物料编码或仓库；须明确验收依据。                                     |
| 5    | 平台     | 匹配预算项       | 按公司、部门、采购类别、期间匹配；不唯一时交财务确认。                         |
| 6    | 平台     | 换算预算参考金额 | 保留交易币种、预算币种、汇率来源及日期；缺少汇率则暂停。                       |
| 7    | 平台     | 检查可用预算     | 校验可用预算（预算总额 − 正式承诺占用 − 预算预占 − 履约已执行）；超额时提示或暂停。 |

### 2. 审批采购申请

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                   |
| ---- | ---------- | ---------------- | ------------------------------------------------ |
| 8    | 平台       | 生成申请审批待办 | 必要信息与预算归属已明确，进入立项审批。         |
| 9    | 申请审批人 | 评估采购必要性   | 判断用途、数量或服务范围是否合理。               |
| 10   | 申请审批人 | 核实费用承担     | 确认承担公司、部门及预算归属。                   |
| 11   | 申请审批人 | 提交申请审批决定 | 通过、退回或拒绝；申请人不能最终审批自己的申请。 |
| 12   | 平台       | 登记申请审批结果 | 审批通过同事务建立预算预占（Pre-encumbrance）并进入任务分配；退回或拒绝不产生预占。 |

### 3. 分配采购任务与核实需求

采购人员选定策略如下。申请人更了解需求，但未必了解采购人员的职责范围和工作安排，不适合承担默认分配责任：

| 方式 | 建议用途 |
| ---- | -------- |
| 系统自动分配 | 根据采购所属公司、采购类别及采购员负责范围匹配；规则明确时直接分配。 |
| 采购负责人分配 | 无匹配人员、多人匹配无法确定，或复杂采购需要协调分工时处理。 |
| 申请人指定 | 可填写建议采购员，由系统校验；通常不直接决定任务归属。 |

根据上述策略，按以下动作执行分配与核实（初期采用明确的固定规则匹配，不引入复杂的负载调度）：

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                                         |
| ---- | ---------- | ---------------- | -------------------------------------------------------------------------------------- |
| 13   | 平台       | 匹配责任采购员   | 按公司和采购类别查询分配规则；结合申请人建议采购员校验有效性。                         |
| 14   | 平台       | 自动分配采购任务 | 匹配结果明确且唯一时自动执行，生成采购员待办。                                         |
| 15   | 采购负责人 | 人工分配采购任务 | 无法自动确定（无匹配人员、多人匹配或复杂采购需协调分工）时执行。                       |
| 16   | 采购员     | 核实采购需求     | 向申请人确认规格、服务范围和实际需求数量；库存仅供参考，不自动扣减申请量；发现分工不合适时由采购负责人改派并保留记录。 |

### 4. 确定采购方式

| 步骤 | 执行角色       | 动作             | 结果或执行条件                                                   |
| ---- | -------------- | ---------------- | ---------------------------------------------------------------- |
| 17   | 采购员         | 查询可用采购协议 | 查看本公司可用的框架采购协议、服务协议及已约定的产品和价格。     |
| 18   | 采购员         | 选择采购方式     | 选择协议下单、RFQ 询价、RFP 方案征集或招标；记录理由和适用范围。 |
| 19   | 平台           | 校验采购方式规则 | 验证协议范围、有效期和额度，或采购类别、金额阈值和例外审批要求。 |
| 20   | 采购方式审批人 | 审批采购方式例外 | 仅偏离公司规则时执行；正常方式按配置确定是否需要审批。           |

### 5. 发布询价或征集文件

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                                         |
| ---- | ---------- | ---------------- | -------------------------------------------------------------------------------------- |
| 21   | 采购员     | 选择受邀供应商   | RFQ、RFP 或招标分支执行；支持邀请已准入供应商或基础建档的潜在供应商（Prospect）；协议下单跳至阶段 8 且必须为已准入合格供应商。 |
| 22   | 平台       | 校验供应商资格范围 | 协议下单严格校验所属公司已准入且启用；RFQ/RFP/招标校验基础法定登记，允许潜在供应商参与竞价寻源，正式准入后置。 |
| 23   | 采购员     | 编制征集文件     | RFQ 明确报价口径；RFP 明确方案要求；招标明确投标要求；均记录范围、截止时间和评审规则。 |
| 24   | 采购员     | 提交征集文件审批 | 按已配置规则确定审批节点。                                                             |
| 25   | 征集审批人 | 提交征集审批决定 | 配置需要人工审批时执行。                                                               |
| 26   | 采购员     | 发布征集文件     | 冻结本轮范围、版本和评审口径；仅已满足审批要求的版本可发布。                           |
| 27   | 采购员     | 发送征集文件     | 首期通过线下渠道送达；保存接收对象和送达凭证。                                         |

### 6. 接收密封响应与集中开标

| 步骤 | 执行角色       | 动作                 | 结果或执行条件                                                                         |
| ---- | -------------- | -------------------- | -------------------------------------------------------------------------------------- |
| 28   | 供应商         | 提交密封响应文件     | RFQ 提交报价，RFP 提交方案与报价，招标提交投标文件；附密封凭证（封条或数字哈希）；截止前提交。 |
| 29   | 采购员         | 登记密封响应凭证     | 盲收登记：仅记录供应商主体、送达时间、版本及密封凭证快照，严禁在截标前拆封、查看或向系统录入价格明细。 |
| 30   | 平台           | 校验递交有效性       | 检查对应征集版本、送达时间是否在截止规则内、密封凭证是否完整；迟交系统自动标记逾期拒收。 |
| 31   | 平台           | 截止接收并封存响应   | 到达截止时间自动关闭接收窗口，状态转为已截止待开标；校验有效密封响应数量，不足按规则转补充征集或例外审批。 |
| 32   | 监标人/采购员  | 集中开标与解密       | 截标后执行；核对密封凭据完整性，集中统一拆封解密各家响应，登记报价明细并生成不可篡改的开标记录表。 |

### 7. 评审与供应商选择

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                       |
| ---- | ---------- | ---------------- | -------------------------------------------------------------------- |
| 33   | 平台       | 生成评审资料     | 统一税费、币种及单位口径；汇总开标结果与评分基准，保留原币价格，不把不同方案强行等同。 |
| 34   | 评审人员   | 提交评审意见     | 按预先确定的价格、技术、服务和交付标准评审；利益冲突须回避。         |
| 35   | 采购员     | 编制授予建议     | 明确供应商、获选明细、数量或金额、选择理由，以及拟形成合同还是订单。 |
| 36   | 采购员     | 提交授予审批     | RFQ 使用比价结果，招标使用评标结果；若获选对象为潜在供应商，系统提示定标后、签单前须完成正式准入。 |
| 37   | 授予审批人 | 提交授予审批决定 | 通过、退回或拒绝。                                                   |
| 38   | 平台       | 生成采购文件或自动核准订单 | 按获批定标生成合同或订单；对无需合同、无偏离且供应商已完全准入启用的 RFQ 订单，同事务自动核准（Auto-approve）并结转预算正式承诺占用，置为已批准待下达；若供应商为潜在供应商或有偏离，生成草稿并锁定待准入获批/人工审批。 |

### 8. 订立合同或下达订单

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                                   |
| ---- | ---------- | ---------------- | -------------------------------------------------------------------------------- |
| 39   | 采购员     | 编制合同草稿     | 需合同分支执行；明确范围、金额或上限、期限、付款条件、验收标准和签署方。         |
| 40   | 采购员     | 提交合同审批     | 无需合同的 RFQ 采购跳过合同动作。                                                |
| 41   | 合同审批人 | 提交合同审批决定 | 按公司配置的商务、财务或法务节点执行。                                           |
| 42   | 平台       | 核准合同并锁定预算 | 审批通过同事务执行前置合规、供应商正式准入（APPROVED/ACTIVE）与额度校验；直接履约合同将预算预占转为正式承诺占用（按获批金额多退少补），锁定生效资格并生成带受控防伪标识的待签文本；未通过释放流程锁。 |
| 43   | 合同签署人 | 签署采购合同     | 基于平台锁定的受控待签版本线下盖章签署；未经核准锁定预算的草稿严禁盖章签署。     |
| 44   | 采购员     | 登记签署凭证     | 上传双方已签章凭据与生效日期。                                                   |
| 45   | 平台       | 激活合同生效状态 | 核验签署凭证完整性；生效日期到达后自动生效，不因预算原因拒绝生效；直接履约合同具备履约执行资格，框架协议开放订单额度。 |
| 46   | 采购员     | 准备订单草稿     | 协议下单引用有效协议；RFQ/RFP 需修改交货期或商务条款时编辑草稿；直接履约合同及已自动核准的 RFQ 订单跳过此动作。 |
| 47   | 采购员     | 提交订单审批     | 协议下单或含偏离修改的订单提审；已自动核准的 RFQ 订单跳过；明确偏离说明、预算与验收标准。 |
| 48   | 订单审批人 | 提交订单审批决定 | 针对协议下单或偏离申请执行核准；最终批准触发最新预算和来源额度校验。             |
| 49   | 平台       | 登记订单生效结果 | 审批通过同事务完成供应商正式准入校验（必须 APPROVED 且 ACTIVE）、预算预占结转正式承诺占用（按获批金额多退少补）、协议额度占用与来源分配；未准入供应商禁止生效。 |
| 50   | 采购员     | 下达正式订单     | 向供应商送达获批版本（人工批准或定标派生自动核准），登记送达依据；不是草稿生成即下单。 |

### 9. 交付与验收

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                     |
| ---- | ---------- | ---------------- | ------------------------------------------------------------------ |
| 51   | 供应商     | 提供交付通知     | 可选；记录预计到货或成果交付信息，不能作为收货或验收完成依据。     |
| 52   | 采购员     | 登记交付通知     | 首期代录线下通知，关联订单或可直接履约合同。                       |
| 53   | 供应商     | 交付采购标的     | 按批次交付实物、服务成果、软件许可或订阅服务。                     |
| 54   | 仓管员     | 核验实物到货     | 实物分支：核对品种、数量及质量要求；专业质检按公司规则另设验收人。 |
| 55   | 仓管员     | 登记收货单       | 实物分支：按来源明细记录本批实际合格数量。                         |
| 56   | 仓管员     | 提交收货过账     | 实物分支：触发库存、履约进度及预算执行记录的原子更新。             |
| 57   | 业务验收人 | 核验非实物交付   | 非实物分支：检查成果、里程碑、授权开通或服务期间。                 |
| 58   | 业务验收人 | 提交验收结果     | 记录通过范围、数量或金额及凭证；不生成库存入库。                   |
| 59   | 平台       | 登记履约确认结果 | 校验累计履约不超有效承诺；同步更新进度和预算执行，不重复记账。     |

### 10. 登记发票与核对应付

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                   |
| ---- | ---------- | ---------------- | ---------------------------------------------------------------- |
| 60   | 供应商     | 提供发票         | 提交对应采购履约的票据及明细。                                   |
| 61   | 财务登记人 | 登记发票         | 保存公司、供应商、币种、票据编号、金额及原件。                   |
| 62   | 财务登记人 | 关联发票依据     | 关联有效订单或直接履约合同，以及对应收货或非实物验收。           |
| 63   | 平台       | 执行发票匹配     | 实物按净收货量核对；服务按已验收金额或范围核对；差异转人工处理。 |
| 64   | 财务登记人 | 提交发票复核     | 锁定待复核分配，避免相同履约重复开票。                           |
| 65   | 财务复核人 | 提交发票复核决定 | 确认或退回；只确认有效、匹配通过的票据。                         |
| 66   | 平台       | 登记已确认应付   | 与有效发票分配同事务生效；不再次消耗采购预算。                   |

### 11. 申请付款与批准支付

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                             |
| ---- | ---------- | ---------------- | -------------------------------------------------------------------------- |
| 67   | 付款申请人 | 创建付款申请     | 本轮先定义已确认应付的普通付款；引用发票、采购依据和合同付款条件。         |
| 68   | 平台       | 检查可申请付款额 | 已确认应付减去有效实付及其他未结清付款申请占用；同一授权下实付不重复扣减。 |
| 69   | 付款申请人 | 提交付款审批     | 记录本次申请金额、计划付款日和收款信息；同事务预留可付额。                 |
| 70   | 付款审批人 | 提交付款审批决定 | 与申请人分离；批准只代表付款授权。                                         |
| 71   | 平台       | 登记付款授权     | 冻结获批金额、收款信息及依据版本，等待真实支付。                           |

### 12. 执行付款与登记结果

| 步骤 | 执行角色   | 动作                 | 结果或执行条件                                                 |
| ---- | ---------- | -------------------- | -------------------------------------------------------------- |
| 72   | 付款经办人 | 执行实际付款         | 按有效付款授权，在企业线下支付渠道执行；平台首期不连接银行。   |
| 73   | 财务登记人 | 登记付款结果         | 引用付款授权，记录实际金额、币种、日期、流水号和凭证。         |
| 74   | 平台       | 校验付款分配         | 检查公司、供应商、授权剩余额及凭证重复；异常实付进入差异工单。 |
| 75   | 财务登记人 | 提交付款登记复核     | 待复核实付计入该授权已用额度，防止并发重复登记。               |
| 76   | 付款复核人 | 提交付款登记复核决定 | 登记人与复核人分离；退回修正记录不代表银行撤销支付。           |
| 77   | 平台       | 更新实付状态         | 按已确认实付结转对应授权占用；允许分次支付和保留未付余额。     |

### 13. 采购收尾与供应商评价

| 步骤 | 执行角色   | 动作               | 结果或执行条件                                             |
| ---- | ---------- | ------------------ | ---------------------------------------------------------- |
| 78   | 采购员     | 确认剩余履约义务   | 有余量时继续跟进或发起关闭审批。                           |
| 79   | 财务人员   | 确认结算完成情况   | 核实发票、实付及未结清付款授权；不得把批准付款视为已付。   |
| 80   | 异常负责人 | 关闭已解决异常     | 保留差异、退货、变更等处理依据。                           |
| 81   | 平台       | 汇总供应商履约指标 | 统计交付及时性、验收通过情况及异常；区分公司和采购类型。   |
| 82   | 采购员     | 提交供应商履约评价 | 基于本次有效业务数据补充评价及证据。                       |
| 83   | 平台       | 登记采购收尾结果   | 履约、结算、预算和异常均满足条件后完成；合同到期另行跟踪。 |

这些动作表示业务责任，不表示每行必须单独点击或独立提交事务。申请获批与预算预占、集中开标解密、合同核准与签前预算锁定（直接履约合同结转承诺占用）、订单批准/定标派生自动核准与预算正式占用、收货过账与履约确认、付款复核与额度结转分别需要原子完成。自动动作发生在对应提交事务中。

申请人提供采购类别和费用承担信息；预算无法唯一匹配时由财务确认。库存不足或充足都不自动改变已申请数量；采购员与申请人确认需求后，由申请人修改并重新提交。

一张申请只属于一家公司。订单按公司、供应商、交易币种及履约方式拆分；预算分配在明细上维护，合同与订单不得对同一履约义务重复占用预算。

## 四个模块在流程中的分工

| 模块       | 管理的流程与结果                                                                 | 与其他模块的协作                                 |
| ---------- | -------------------------------------------------------------------------------- | ------------------------------------------------ |
| 采购管理   | 申请、任务分配、采购方式、征集与响应、评审授予、协议合同、订单、变更、非实物验收 | 向财务提供采购承诺和履约依据；使用供应商准入结果 |
| 供应商管理 | 档案、资质、按公司准入、启停与履约评价                                           | 为采购提供可用供应商（含潜在供应商参与竞争、准入后置控制），基于真实履约更新绩效 |
| 库存与仓储 | 实物收货、退货、领用、盘点和库存流水                                             | 向采购和财务提供实物履约依据；不处理服务入库     |
| 财务管理   | 预算分配及流水、发票与应付、付款申请、付款授权、实际付款登记                     | 校验采购承诺预算和可付额度；与履约、支付记录核对 |

合同属于采购模块，非实物验收属于采购履约业务；不额外拆出合同系统或项目管理系统。通用审批、权限、附件、审计和跨模块事务仍由公共能力支持。

## 预算在流程中如何变化

以下以含税金额、履约确认转执行的管理口径说明；各公司实际采用的口径由规则配置。实物以合格收货为履约依据，服务、许可和订阅等以获确认的验收范围为依据。跨币种先按配置的汇率口径换算为预算币种，不直接相加不同币种金额：

| 业务动作                         | 预算变化                                                         |
| -------------------------------- | ---------------------------------------------------------------- |
| 申请审批通过                     | 建立预算预占（Pre-encumbrance），可用预算减少                    |
| 订单批准（含定标自动核准）或直接履约合同核准锁定 | 预占转为正式承诺占用（Encumbrance），多退少补（释放估算差额）    |
| 申请取消或寻源失败终止           | 释放对应预算预占，可用预算恢复                                   |
| 分批收货或非实物验收             | 对应金额从“承诺占用”转为“已执行”，可用预算不重复减少             |
| 关闭未履约余量                   | 释放未履约部分承诺占用，可用预算恢复                             |
| 合法退货且不补货                 | 冲减对应已执行金额，可用预算恢复                                 |
| 发票确认、付款登记               | 不再扣减同一笔采购预算                                           |

例如某公司使用人民币预算且订单同为人民币，总预算为 100,000 元，采购申请预估金额为 22,000 元：申请审批通过后建立预占 22,000 元，可用预算变为 78,000 元（有效防止寻源期间预算被并发抢占）；寻源比价后订单批准或直接履约合同核准锁定时金额为 20,000 元，平台将预占结转为 20,000 元正式承诺占用，并释放 2,000 元估算差额，可用预算调整为 80,000 元；先收货 12,000 元后，承诺占用变为 8,000 元，已执行 12,000 元，可用仍是 80,000 元。如果随后批准取消剩余采购，释放未履约承诺占用 8,000 元，可用预算恢复为 88,000 元；已收货的 12,000 元继续完成发票核对和付款登记。

## 什么情况下算完成

交付和结算分别判断，不把“订单关闭”直接理解为“已付款”：

- **交付完成**：实物订单待收数量为零，或非实物订单约定成果、里程碑及服务期间均已验收；剩余义务已实际履行或经批准取消。此时可以关闭订单交付，未处理发票和付款仍继续。
- **发票核对完成**：有效收货或非实物验收有相应的有效发票覆盖，相关匹配差异和财务复核已处理。
- **付款登记完成**：对应已确认应付的付款记录已复核，没有尚未解决的登记差异。
- **采购流程收尾完成**：上述环节均已处理，未履约预算占用已释放，关联异常已解决；完全取消且未发生履约及费用的采购无需再开票或付款。

这些是平台展示和核查的业务维度，具体状态由有效单据及明细汇总得出，不能通过一个“全部完成”按钮跳过必要步骤。

## 智能助手如何参与

助手可检查需求、查询库存和预算、推荐内部供应商、整理报价、解释交付或发票差异，并在授权范围内准备草稿、提交审批和调用获准动作。正式准入、业务审批、库存过账、财务复核和付款登记仍由对应人员处理。

助手通过业务 API 使用平台，与业务页面执行相同规则。助手停机或升级时，业务人员仍可完整办理上述流程。
