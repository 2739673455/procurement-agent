# 采购业务平台

本目录用于建设独立部署的业务后端，使用 Python + FastAPI，采用模块化单体架构。

包含四个业务模块：

- 采购管理：采购申请、寻源、协议合同、订单、履约与变更。
- 供应商管理：供应商档案、准入与绩效。
- 财务管理：采购预算、发票与应付、付款申请及实付登记。
- 库存与仓储：库存流水、收货与退货。

用户、组织、权限、审批协调和业务审计由业务后端统一管理。Agent 服务独立部署，通过受控业务 API 调用本系统，不直接访问业务数据库。

平台面向多公司、多币种采购，覆盖实物、服务、软件许可及订阅等采购类型。业务单据按所属公司管理权限、审批和预算，记录交易币种及必要的汇率信息；实物采购通过收货入库确认履约，服务、软件许可及订阅等采购通过成果、交付或服务期间验收确认履约，不要求全部进入库存。预算执行口径及已付款退货等规则按各公司制度确定。

本文描述目标业务流程。字段设计见[数据库 v3](docs/DATABASE.md)，实施按[交付切片](docs/DESIGN.md#141-工程落地与验收)推进；目前尚未实现业务代码、迁移或数据库验证。

## 采购前置条件

公司与组织、人员权限、审批规则、采购类别、供应商档案、币种与汇率配置、预算等由对应管理人员建立并持续维护；涉及实物采购时，还需维护物料、仓库和期初库存。这些属于平台基础管理，不是每次采购都要重复执行的步骤。

单次采购只检查所需配置和数据是否可用。发现缺项时，由责任人补充；新供应商准入、预算调整等可作为本次采购触发的配套流程，完成后再推进受影响的业务环节。

## 采购流程总览

流程以 IBM TRIRIGA 11.6 的采购生命周期为参考，并按本项目的四模块边界、多公司、多币种和非实物采购要求调整。参考来源、业务对象、状态及配套动作见[采购业务平台详细设计](docs/DESIGN.md)。

主线是提出需求、申请审批、分配采购任务、核实需求、确定采购方式、形成采购承诺、履约验收、发票核对、付款申请、实际付款及收尾。采购方式有以下分支：

- **协议下单**：已有适用的框架采购协议或服务协议，直接引用协议准备订单，跳过本次竞争寻源。
- **RFQ 询价**：先发询价，再接收报价，经比价和审批形成订单。
- **RFP 方案征集**：先征集方案与报价，再综合评审，按批准结果准备订单或合同。
- **招标**：发布招标文件、接收投标、评标及授予，通常进入合同订立。

询价与报价是两个阶段，招标与投标也分别由采购方和供应商执行。直接采购或单一来源须符合公司规则及例外审批，不允许通过伪造报价凑足家数。

以下每一行只指定一个执行角色和一个业务动作。“平台”表示业务后端自动执行；供应商首期在线下参与，由内部人员登记凭证。阶段编号表示阅读顺序，只有适用分支才执行；分批交付、开票、付款可以交错进行。审批与签署、批准付款与实际支付均分别记录。

## 逐步执行流程

### 1. 提交采购申请

| 步骤 | 执行角色 | 动作             | 结果或执行条件                                                                                                                                     |
| ---- | -------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 申请人   | 选择采购所属公司 | 仅可选择获授权公司；只有一个可选公司时默认带出。                                                                                                   |
| 2    | 申请人   | 填写采购申请     | 记录类型、类别、用途、数量或服务范围、交付要求、预计金额、币种和费用承担部门；可填写建议采购员（由系统校验，供分配参考，通常不直接决定任务归属）。 |
| 3    | 申请人   | 提交采购申请     | 一张申请只属于一家公司；混合类型按明细记录。                                                                                                       |
| 4    | 平台     | 校验申请完整性   | 非实物无需物料编码或仓库；须明确验收依据。                                                                                                         |
| 5    | 平台     | 匹配预算项       | 按公司、部门、采购类别、期间匹配；不唯一时交财务确认。                                                                                             |
| 6    | 平台     | 换算预算参考金额 | 保留交易币种、预算币种、汇率来源及日期；缺少汇率则暂停。                                                                                           |
| 7    | 平台     | 检查可用预算     | 校验可用预算（预算总额 − 正式承诺占用 − 预算预占 − 履约已执行）；超额时提示或暂停。                                                                |

### 2. 审批采购申请

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                                      |
| ---- | ---------- | ---------------- | ----------------------------------------------------------------------------------- |
| 8    | 平台       | 生成申请审批待办 | 必要信息与预算归属已明确，进入立项审批。                                            |
| 9    | 申请审批人 | 评估采购必要性   | 判断用途、数量或服务范围是否合理。                                                  |
| 10   | 申请审批人 | 核实费用承担     | 确认承担公司、部门及预算归属。                                                      |
| 11   | 申请审批人 | 提交申请审批决定 | 通过、退回或拒绝；申请人不能最终审批自己的申请。                                    |
| 12   | 平台       | 登记申请审批结果 | 审批通过同事务建立预算预占（Pre-encumbrance）并进入任务分配；退回或拒绝不产生预占。 |

### 3. 分配采购任务与核实需求

采购人员选定策略如下。申请人更了解需求，但未必了解采购人员的职责范围和工作安排，不适合承担默认分配责任：

| 方式           | 建议用途                                                             |
| -------------- | -------------------------------------------------------------------- |
| 系统自动分配   | 根据采购所属公司、采购类别及采购员负责范围匹配；规则明确时直接分配。 |
| 采购负责人分配 | 无匹配人员、多人匹配无法确定，或复杂采购需要协调分工时处理。         |
| 申请人指定     | 可填写建议采购员，由系统校验；通常不直接决定任务归属。               |

根据上述策略，按以下动作执行分配与核实（初期采用明确的固定规则匹配，不引入复杂的负载调度）：

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                                                                         |
| ---- | ---------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 13   | 平台       | 匹配责任采购员   | 按公司和采购类别查询分配规则；结合申请人建议采购员校验有效性。                                                         |
| 14   | 平台       | 自动分配采购任务 | 匹配结果明确且唯一时自动执行，生成采购员待办。                                                                         |
| 15   | 采购负责人 | 人工分配采购任务 | 无法自动确定（无匹配人员、多人匹配或复杂采购需协调分工）时执行。                                                       |
| 16   | 采购员     | 核实采购需求     | 向申请人确认规格、服务范围和实际需求数量；库存仅供参考，不自动扣减申请量；发现分工不合适时由采购负责人改派并保留记录。 |

### 4. 确定采购方式

| 步骤 | 执行角色       | 动作             | 结果或执行条件                                                                   |
| ---- | -------------- | ---------------- | -------------------------------------------------------------------------------- |
| 17   | 采购员         | 查询可用采购协议 | 查看本公司可用的框架采购协议、服务协议及已约定的产品和价格。                     |
| 18   | 采购员         | 选择采购方式     | 选择协议下单、RFQ 询价、RFP 方案征集或招标；记录理由和适用范围。                 |
| 19   | 平台           | 校验采购方式规则 | 验证协议范围、有效期和额度，或采购类别、金额阈值和例外审批要求。                 |
| 20   | 采购员         | 提交采购方式决定 | 保存本次范围、规则版本及例外理由；平台生成所需审批待办，免审批也记录规则判断。   |
| 21   | 采购方式审批人 | 审批采购方式决定 | 按公司规则处理正常方式及例外；明确免审批规则除外。未批准决定不得发布征集或下单。 |

### 5. 发布询价或征集文件

| 步骤 | 执行角色   | 动作               | 结果或执行条件                                                                                                 |
| ---- | ---------- | ------------------ | -------------------------------------------------------------------------------------------------------------- |
| 22   | 采购员     | 选择受邀供应商     | RFQ/RFP/招标分支执行，允许基础建档的潜在供应商参与；协议下单跳过阶段 5–7，进入阶段 8 的订单准备步骤。          |
| 23   | 平台       | 校验供应商资格范围 | 协议下单严格校验所属公司已准入且启用；RFQ/RFP/招标校验基础法定登记，允许潜在供应商参与竞价寻源，正式准入后置。 |
| 24   | 采购员     | 编制征集文件       | RFQ 明确报价口径；RFP 明确方案要求；招标明确投标要求；均记录范围、截止时间和评审规则。                         |
| 25   | 采购员     | 提交征集文件审批   | 按已配置规则确定审批节点。                                                                                     |
| 26   | 征集审批人 | 提交征集审批决定   | 配置需要人工审批时执行。                                                                                       |
| 27   | 采购员     | 发布征集文件       | 冻结本轮范围、版本和评审口径；仅已满足审批要求的版本可发布。                                                   |
| 28   | 采购员     | 发送征集文件       | 首期通过线下渠道送达；保存接收对象和送达凭证。                                                                 |

### 6. 接收密封响应与集中开标

| 步骤 | 执行角色 | 动作               | 结果或执行条件                                                                                             |
| ---- | -------- | ------------------ | ---------------------------------------------------------------------------------------------------------- |
| 29   | 供应商   | 提交密封响应文件   | RFQ 提交报价，RFP 提交方案与报价，招标提交投标文件；附密封凭证（封条或数字哈希）；截止前提交。             |
| 30   | 采购员   | 登记密封响应凭证   | 盲收登记：仅记录供应商主体、送达时间、版本及密封凭证快照，严禁在截标前拆封、查看或向系统录入价格明细。     |
| 31   | 平台     | 校验递交有效性     | 检查对应征集版本、送达时间是否在截止规则内、密封凭证是否完整；迟交系统自动标记逾期拒收。                   |
| 32   | 平台     | 截止接收并封存响应 | 到达截止时间自动关闭接收窗口，状态转为已截止待开标；校验有效密封响应数量，不足按规则转补充征集或例外审批。 |
| 33   | 监标人   | 授权集中开标       | 实际用户须独立于本轮采购员及盲收经办人；核对截止、密封和最低响应要求，缺少合格见证人保持待办。             |
| 34   | 平台     | 执行集中解密       | 验证独立见证授权后同事务解密、生成开标记录和审计；不提供采购员单人解密入口。                               |

### 7. 评审与供应商选择

| 步骤 | 执行角色   | 动作                       | 结果或执行条件                                                                                                                                                     |
| ---- | ---------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 35   | 平台       | 生成评审资料               | 统一税费、币种及单位口径；汇总开标结果与评分基准，保留原币价格，不把不同方案强行等同。                                                                             |
| 36   | 评审人员   | 提交评审意见               | 按预先确定的价格、技术、服务和交付标准评审；利益冲突须回避。                                                                                                       |
| 37   | 采购员     | 编制授予建议               | 明确供应商、获选明细、数量或金额、选择理由，以及拟形成合同还是订单。                                                                                               |
| 38   | 采购员     | 提交授予审批               | RFQ 使用比价结果，RFP 使用综合方案评审结果，招标使用评标结果；保留对应响应和范围版本。                                                                             |
| 39   | 授予审批人 | 提交授予审批决定           | 通过、退回或拒绝。                                                                                                                                                 |
| 40   | 平台       | 生成采购文件并确定核准路径 | RFQ/RFP 无需合同、全关键字段无偏离且公司规则允许、供应商已准入启用时，经来源和预算校验自动核准；未准入进入准入待办，其余生成采购员送审待办；需合同则生成合同草稿。 |

### 8. 订立合同或下达订单

| 步骤 | 执行角色   | 动作               | 结果或执行条件                                                                                                                                                                                                                                                                      |
| ---- | ---------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 41   | 采购员     | 编制合同草稿       | 需合同分支执行；固定范围合同送审前形成可审阅的派生订单草稿，明确范围、金额或上限、期限、付款条件、验收标准和签署方。                                                                                                                                                                |
| 42   | 采购员     | 提交合同审批       | 需合同的采购执行；无需合同的采购均跳过合同动作。固定范围合同连同可审阅派生订单及预算分配送审。                                                                                                                                                                                      |
| 43   | 合同审批人 | 提交合同审批决定   | 按公司配置的商务、财务或法务节点执行。                                                                                                                                                                                                                                              |
| 44   | 平台       | 核准合同并锁定预算 | 审批通过同事务执行前置合规、供应商正式准入（APPROVED/ACTIVE）与额度校验；固定范围合同同事务核准送审时已冻结的派生订单，由订单明细将预算预占转为正式承诺占用（按本订单范围对应份额多退少补），订单待合同生效才可执行，锁定生效资格并生成带受控防伪标识的待签文本；未通过释放流程锁。 |
| 45   | 合同签署人 | 签署采购合同       | 基于平台锁定的受控待签版本线下盖章签署；未经核准锁定预算的草稿严禁盖章签署。                                                                                                                                                                                                        |
| 46   | 采购员     | 登记签署凭证       | 上传双方已签章凭据与生效日期。                                                                                                                                                                                                                                                      |
| 47   | 平台       | 激活合同生效状态   | 固定范围合同只解锁已核准派生订单，不重复占预算；无确定承诺的框架生效本身不占预算，但后续每张订单批准须占预算及协议额度；保底承诺须提前落实为订单。                                                                                                                                  |
| 48   | 采购员     | 准备订单草稿       | 协议下单引用有效合同；RFQ/RFP 等来源草稿按需要补齐。已随合同或定标核准的订单不重复编制；补齐准入后主动重评核准路径。                                                                                                                                                                |
| 49   | 采购员     | 提交订单审批       | 适用于协议下单、例外采购、实质偏离、公司要求人工审批及准入后重评未获自动核准的订单；已经合法核准的订单跳过。                                                                                                                                                                        |
| 50   | 订单审批人 | 提交订单审批决定   | 审核公司要求的订单或偏离，不能仅按 RFQ/RFP 名称判断免审；最终批准时校验完整来源、准入及预算。                                                                                                                                                                                       |
| 51   | 平台       | 登记订单核准结果   | 锁定跨版本稳定需求项及预算账户，只结转本订单范围对应的预占，保留未下单余额；范围和各账户足额才同时更新占用、协议额度及来源分配。                                                                                                                                                    |
| 52   | 采购员     | 下达正式订单       | 必须核准、READY 且当前供应商允许新采购；合同订单须合同已生效。登记送达依据，合同签署文件可作为依据；仅合同生效不能代替订单下达。                                                                                                                                                    |

### 9. 交付与验收

| 步骤 | 执行角色   | 动作             | 结果或执行条件                                                                                                         |
| ---- | ---------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 53   | 供应商     | 提供交付通知     | 可选；记录预计到货或成果交付信息，不能作为收货或验收完成依据。                                                         |
| 54   | 采购员     | 登记交付通知     | 首期代录线下通知，关联订单。                                                                                           |
| 55   | 供应商     | 交付采购标的     | 按批次交付实物、服务成果、软件许可或订阅服务。                                                                         |
| 56   | 仓管员     | 登记实物到货     | 记录实到数量、外观、来源明细和保管位置；到货不增加可用库存、不确认履约或预算执行。                                     |
| 57   | 仓管员     | 登记当场拒收     | 仅明显破损、错货等分支：记录数量、原因和交接凭证；未入库无需先入库再退货。                                             |
| 58   | 平台       | 确定到货检验要求 | 按公司、采购类别和风险规则决定是否专业质检；配置缺失阻止放行。                                                         |
| 59   | 质检员     | 提交质量检验结果 | 需专业质检时执行；按到货明细记录合格、不合格和待复检数量及证据。                                                       |
| 60   | 仓管员     | 确认简化验收结果 | 仅规则允许免专业质检时执行，仍核验规格、数量、外观和凭证。                                                             |
| 61   | 仓管员     | 登记合格收货单   | 只引用已通过检验或简化验收的数量；待检和不合格数量留在独立保管台账。                                                   |
| 62   | 仓管员     | 提交收货过账     | 订单已下达且执行资格有效；按合格量原子更新库存、履约和预算。历史履约不因供应商禁止新采购而自动中止，专项冻结另行判断。 |

### 13. 采购收尾与供应商评价

| 步骤 | 执行角色   | 动作               | 结果或执行条件                                                                         |
| ---- | ---------- | ------------------ | -------------------------------------------------------------------------------------- |
| 87   | 采购员     | 确认剩余履约义务   | 有余量时继续跟进或发起关闭审批。                                                       |
| 88   | 财务人员   | 确认结算完成情况   | 核实发票、实付、预付核销及授权余额；待补正、待核实、未核销预付或退款未解决时不能收尾。 |
| 89   | 异常负责人 | 关闭已解决异常     | 由工单按类别指派的责任人执行；相关业务处理完成后方可关闭，保留证据。                   |
| 90   | 平台       | 汇总供应商履约指标 | 统计交付及时性、验收通过情况及异常；区分公司和采购类型。                               |
| 91   | 采购员     | 提交商务配合评价   | 仅填写采购员负责维度；其他维度由对应责任角色独立提交。                                 |
| 92   | 平台       | 登记采购收尾结果   | 履约、结算、预算和异常均满足条件后完成；合同到期另行跟踪。                             |

供应商评价按采购类型执行适用分支，可在收尾前后独立完成：

| 编号 | 执行角色     | 动作             | 条件或结果                                                 |
| ---- | ------------ | ---------------- | ---------------------------------------------------------- |
| E01  | 仓管员       | 提交交付配合评价 | 实物采购，依据到货与交接记录。                             |
| E02  | 质检员       | 提交质量评价     | 有专业检验时，引用检验结论。                               |
| E03  | 业务验收人   | 提交服务成果评价 | 非实物采购，引用已确认验收。                               |
| E04  | 财务人员     | 提交票款配合评价 | 基于真实票款处理情况，不把本公司付款延误归责供应商。       |
| E05  | 平台         | 汇总供应商评价   | 按适用维度及规则权重汇总，必填缺项显示待完善，不伪造评分。 |
| E06  | 供应商管理员 | 复核发布评价     | 保留各角色原始评分、证据与规则版本；修改后重新复核。       |

所有采购最终通过订单执行；固定范围合同派生的订单复用合同审批，合同生效前不得履约或付款，签署文件可作为订单送达依据。合同与订单的范围及预算规则见[统一订单执行](docs/DESIGN.md#52-合同约束与统一订单执行)。

这些动作表示业务责任，不表示每行必须单独点击或独立提交事务。申请获批与预算预占、集中开标解密、合同核准与签前预算锁定（通过合同派生订单明细结转承诺占用）、订单批准/定标派生自动核准与预算正式占用、收货过账与履约确认、付款复核与额度结转分别需要原子完成。自动动作发生在对应提交事务中。

申请人提供采购类别和费用承担信息；预算无法唯一匹配时由财务确认。库存不足或充足都不自动改变已申请数量；采购员与申请人确认需求后，关键内容变更由申请人创建修订提案并重新审批；受影响范围暂停新增采购，原批准预占保留到提案批准后原子调整，已有订单不被申请修订覆盖。

一张申请只属于一家公司。订单按公司、供应商、交易币种及履约方式拆分；预算分配在明细上维护，合同与订单不得对同一履约义务重复占用预算。

待检保管、当场拒收及未入库不合格品退回不产生采购库存入库或预算执行；其数量及交接仍须记录。已入库后的退货走 B22–B25；未入库的退回登记实际交接，不能使用已入库退货单。详细数量控制和验收审批规则见[履约控制](docs/DESIGN.md#71-到货检验退货与非实物验收控制)。

## 四个模块在流程中的分工

| 模块       | 管理的流程与结果                                                                 | 与其他模块的协作                                                                 |
| ---------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 采购管理   | 申请、任务分配、采购方式、征集与响应、评审授予、协议合同、订单、变更、非实物验收 | 向财务提供采购承诺和履约依据；使用供应商准入结果                                 |
| 供应商管理 | 档案、资质、按公司准入、启停与履约评价                                           | 为采购提供可用供应商（含潜在供应商参与竞争、准入后置控制），基于真实履约更新绩效 |
| 库存与仓储 | 实物收货、退货、领用、盘点和库存流水                                             | 向采购和财务提供实物履约依据；不处理服务入库                                     |
| 财务管理   | 预算分配及流水、发票与应付、付款申请、付款授权、实际付款登记                     | 校验采购承诺预算和可付额度；与履约、支付记录核对                                 |

合同属于采购模块，非实物验收属于采购履约业务；不额外拆出合同系统或项目管理系统。通用审批、权限、附件、审计和跨模块事务仍由公共能力支持。

以下为条件分支，不是每次采购都要执行的主流程。对应问题解决后，回到受影响的校验、审批或履约步骤。

| -------- | -------------------------- | ------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B01      | 资料缺失                   | 平台                | 生成资料补充提示       | 暂停受影响的提交。                                                                                                                                               |
| B02      | 资料缺失                   | 申请人              | 补充申请资料           | 保存完整的采购需求。                                                                                                                                             |

| B33      | 纠错待审批                 | 纠错审批人          | 提交纠错审批决定       | 获准后才能执行对应修正。                                                                                                                                         |
| B34      | 纠错获批                   | 平台                | 执行获准的反向记账     | 保留原流水；付款更正须保留资金事实及冻结；仅核实后调整分配，不等于银行退款。                                                                                     |

| B35 | 获批申请需修改或终止 | 申请人 | 提交申请修订或终止提案 | 指定未下单范围及新版本；冻结受影响范围，保留旧有效预占。 |
| B36 | 修订/终止待审批 | 申请审批人 | 提交提案审批决定 | 不能覆盖已下单范围；平台批准时原子调整对应预占、范围及有效版本，预算不足全部回滚；退回保持范围冻结，拒绝则恢复原批准范围、清空活跃提案，旧预占不动。 |
| B36a | 修订/终止提案需撤回 | 提案提交人 | 撤回未批准提案 | 平台同事务恢复原批准范围、清空 active_change_id，旧预占不动，保留草稿历史；已批准提案不得撤回。 |
| B36b | 修订/终止提案被退回 | 提案提交人 | 修改并重新提交提案 | 保持 REVISING 冻结，建立新内容版本；沿用原有效预占。 |
| B37 | 放弃当前寻源需求 | 采购员 | 提交需求终止提案 | 仅关闭失败征集轮次不释放预占；原申请审批人批准后，平台只释放放弃范围的预占。 |
| B38 | 合同无法签成或拟终止 | 采购员 | 提交合同终止申请 | 列出派生订单、签署事实和未执行范围；不因签署超时自动释放。 |
| B39 | 合同终止待审批 | 合同审批人 | 提交终止审批决定 | 与合同激活互斥；平台原子终止未执行订单并释放其占用，有履约/发票/预付先处理差异。 |
| B40 | 支付结果未知或待证实失败 | 付款经办人 | 提交执行结果核实凭证 | 未知结果持续冻结；真实已出款后退回属于退款，不视为未执行。 |
| B41 | 执行失败待核实 | 付款复核人 | 确认执行未发生或确已失败 | 独立核实后平台释放对应执行冻结，原授权可重试；真实出款/未知结果不可直接释放。 |
| B42 | 未执行授权不再需要 | 付款申请人 | 提交剩余授权撤销申请 | 指定未付且无未决执行的余额，不删除已有实付。 |
| B43 | 授权撤销待审批 | 付款审批人 | 审批剩余授权撤销 | 平台仅释放获批未执行余额；待补正/待核实款保持冻结。 |
| B44 | 收到供应商问题 | 采购员 | 登记澄清请求 | 关联具体征集版本，后续统一答复相关受邀方；详见 DESIGN 配套动作 S04–S07。 |
| B45 | 澄清改变范围或截止安排 | 采购员 | 提交征集修订 | 重新审批及发布，明确补遗或新轮次，不直接覆盖已批准文件。 |
| B46 | 响应均不合格或数量不足 | 采购员 | 提交重新征集申请 | 保留失败轮次并按规则重新审批；若放弃需求走 B37，不自动释放预占。 |
| B47 | 合同/订单需改变关键条款 | 采购员 | 提交变更包 | 指定基准版本、范围及预算差额，详见 DESIGN 变更控制和 S13–S16。 |
| B48 | 变更包待审批 | 变更审批人 | 提交变更审批决定 | 必要时补双方确认；平台同事务更新有效版本、预算差额、协议额度和未履约义务，历史事实不抹除。 |

## 预算在流程中如何变化

以下以含税金额、履约确认转执行的管理口径说明；各公司实际采用的口径由规则配置。实物以合格收货为履约依据，服务、许可和订阅等以获确认的验收范围为依据。跨币种先按配置的汇率口径换算为预算币种，不直接相加不同币种金额：

| 业务动作                                     | 预算变化                                                      |
| -------------------------------------------- | ------------------------------------------------------------- |
| 申请审批通过                                 | 建立预算预占（Pre-encumbrance），可用预算减少                 |
| 订单批准（含定标自动核准）或合同审批派生核准 | 预占转为正式承诺占用（Encumbrance），多退少补（释放估算差额） |
| 经批准取消申请或放弃寻源需求                 | 仅释放批准放弃范围的预占；失败轮次本身不释放                  |
| 分批收货或非实物验收                         | 对应金额从“承诺占用”转为“已执行”，可用预算不重复减少          |
| 关闭未履约余量                               | 释放未履约部分承诺占用，可用预算恢复                          |
| 合法退货且不补货                             | 冲减对应已执行金额，可用预算恢复                              |
| 发票确认、付款登记                           | 不再扣减同一笔采购预算                                        |

例如某公司使用人民币预算且订单同为人民币，总预算为 100,000 元，采购申请预估金额为 22,000 元：申请审批通过后建立预占 22,000 元，可用预算变为 78,000 元（有效防止寻源期间预算被并发抢占）；寻源比价后订单批准或合同审批派生核准时金额为 20,000 元，平台将预占结转为 20,000 元正式承诺占用，并释放 2,000 元估算差额，可用预算调整为 80,000 元；先收货 12,000 元后，承诺占用变为 8,000 元，已执行 12,000 元，可用仍是 80,000 元。如果随后批准取消剩余采购，释放未履约承诺占用 8,000 元，可用预算恢复为 88,000 元；已收货的 12,000 元继续完成发票核对和付款登记。

## 什么情况下算完成

交付和结算分别判断，不把“订单关闭”直接理解为“已付款”：

- **交付完成**：实物订单待收数量为零，或非实物订单约定成果、里程碑及服务期间均已验收；剩余义务已实际履行或经批准取消。此时可以关闭订单交付，未处理发票和付款仍继续。
- **发票核对完成**：有效收货或非实物验收有相应的有效发票覆盖，相关匹配差异和财务复核已处理。
- **付款登记完成**：对应已确认应付的付款记录已复核，没有尚未解决的登记差异。
- **采购流程收尾完成**：上述环节均已处理，未履约预算占用已释放，关联异常已解决；完全取消且未发生履约及费用的采购无需再开票或付款。

这些是平台展示和核查的业务维度，具体状态由有效单据及明细汇总得出，不能通过一个“全部完成”按钮跳过必要步骤。

## 智能助手如何参与

助手可检查需求、查询库存和预算、推荐内部供应商、整理报价、解释交付或发票差异，并在授权范围内准备草稿、提交审批和调用获准动作。正式准入、业务审批、库存过账、财务复核和付款登记仍由对应人员处理。

助手通过业务 API 使用平台，与业务页面执行相同规则。助手停机或升级时，业务人员仍可完整办理上述流程。

预付余额、支付冻结、待核实记录及核销并发规则见[付款额度与一致性](docs/DESIGN.md#8-发票预付与付款控制)。
