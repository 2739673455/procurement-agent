## 2. 流程分支及责任边界

基础数据维护是前置条件。单次采购从申请开始，经业务审批立项后，由系统或采购负责人分配采购任务并核实需求，再选择采购方式；采购负责人可在不改变申请内容的情况下改派采购员，保留交接记录。

| 方式 | 适用判断 | 寻源输入与供应商输出 | 后续路径 |
| ---- | -------- | -------------------- | -------- |
| 协议下单 | 本公司已有生效且覆盖本次范围的框架采购协议或服务协议 | 核对约定品目、价格、有效期和可用额度；必须为已准入合格供应商 | 申请明细关联协议明细，准备订单 |
| RFQ 询价 | 需求规格和价格比较口径已明确 | 询价单 → 密封报价凭证 → 集中开标解密 | 比价、授予审批、无偏离订单自动核准（或有偏离订单草稿） |
| RFP 方案征集 | 需比较解决方案、交付方法或服务能力 | 方案征集文件 → 密封方案及报价凭证 → 集中开标解密 | 综合评审、授予审批、订单或合同草稿 |
| 招标 | 公司采购制度要求采用招标方式 | 招标文件 → 密封投标响应凭证 → 集中开标解密 | 评标、授予审批、合同草稿 |
| 例外采购 | 单一来源、紧急采购或响应数量不足等有充分依据 | 例外申请、理由和支撑材料 | 经授权审批后按指定路径执行，仍需合同或订单及预算校验 |

询价、报价、评审是不同阶段，分别对应征集文件、供应商响应和授予记录。RFQ 的结果称比价和供应商选择；招标的结果称评标及定标。多个方式可以复用版本、附件、邀请与审批基础能力，但不能把供应商报价直接写进询价单覆盖原始要求。

需求明细可以拆为多个采购包，同公司、同预算口径且适合一起评审的需求也可以合并寻源。分包、合并和分配均保留来源明细及数量或金额；不得跨公司合并成一张对外采购文件。申请人填写公司和需求信息，财务负责无法自动匹配的预算归属；采购员不能以库存数量自行改写需求。

| 采购 | 采购合同 | 标准合同、框架采购协议、服务协议；分别保存类型、签署、生效条件和执行模式 |
| 采购 | 合同明细及履约计划 | 约定范围、价格、额度、期间、里程碑、验收及付款条件 |
| 采购 | 采购订单 | 引用授予或协议依据；明细记录履约标的、预算分配和来源范围 |
| 采购 | 采购变更单 | 唯一目标合同或订单、目标基准版本、变更前后值、原因、金额差额及审批 |
| 采购 | 交付通知 | 供应商预计交付信息、来源承诺明细及附件；不更新库存或预算 |
| 采购 | 非实物验收单 | 关联直接履约合同或订单明细；成果、里程碑、许可或服务期间及通过数量或金额 |
| 库存 | 物料档案与库存余额 | 只记录实物物料，管理仓库、库位、现存量与批次；不记录服务及虚拟资产 |
| 库存 | 收货及退货单 | 实物履约和库存凭证，关联采购承诺明细；保留实收、退回及冲销关系 |
| 供应商 | 档案、公司准入和绩效 | 区分潜在供应商（PROSPECT，参与竞争寻源）与正式准入合格供应商（APPROVED，签约下单）；准入状态不能由报价记录代替 |
| 财务 | 预算账户及分配 | 公司、预算币种、期间、部门及可选项目维度；采购明细可以拆分承担额度 |
| 财务 | 预算预占、承诺与执行流水 | 对采购申请建立预占，对确定承诺（订单/直接履约合同）正式占用，执行、释放或冲销，关联当时汇率快照 |
| 财务 | 发票及应付分配 | 原始票据、订单或合同明细、收货或验收依据、匹配结果、复核状态 |
| 财务 | 付款申请 | 应付来源、本次金额、计划日期、收款信息；提交后占用可申请额 |
| 财务 | 付款授权 | 付款申请获批版本的不可变授权结果及有效余额；不是已付款记录 |
| 财务 | 付款登记 | 实际支付凭证、授权分配、发票分配及复核结果；支持一次授权分次支付 |
| 公共能力 | 审批、附件、审计、异常与幂等 | 绑定业务对象和内容版本；不能绕过领域动作直接更新状态 |

采购承诺是“获准履行和支付的采购义务”的领域概念，由直接履约合同或正式订单承载。单据关系必须落到明细和版本，不只保存合同号或订单号字符串。

## 4. 合同、订单与预算

### 4.1 两种执行模式与订单审批规则

- **按协议下单**：框架采购协议或服务协议约定条件及额度，具体采购通过订单承诺。协议上限用于控制可下单额度，申请批准时预占预算，订单批准时将预占结转为正式承诺占用（多退少补）；协议和订单不能各扣一次预算。
- **合同直接履约**：合同已明确需执行的范围、期间或里程碑，可直接收货、验收和结算；申请批准时预占预算，合同核准时将预占结转为正式承诺占用（多退少补）并锁定生效资格，不强制为同一义务再建订单。

合同类型与执行模式分开。例如服务协议既可能约定按次下单，也可能直接承诺一年的服务。创建时必须明确模式，生效后不能直接切换。存在保底采购金额的框架协议需单独表达承诺，不能仅按“上限不占预算”处理；首批切片不支持时应阻止其生效并提示缺少能力。

合同审批和双方签署分别记录。实行“签前锁定”内控闭环：直接履约合同在合同审批通过时，系统同事务执行生效前置条件校验并将预算预占结转为正式承诺占用（多退少补释放估算差额），锁定生效资格并生成带防伪标识的受控待签版本；只有经核准锁定的版本才允许由法定授权人线下盖章签署。签署登记后平台核验凭证完整性并激活生效状态，严禁在签后阶段因预算原因拒绝生效。若双方最终未达成签署，须走合同作废/终止流程释放锁定的预算。

**定标派生免审与差异化审批规则**：
- **定标派生免除重复审批**：经比价或评审获批的 RFQ/RFP 定标结果（授予决定），已法定锁定了获选供应商、明细行、单价、数量、总额及预算承担信息。由获批定标结果直接派生且条款完全一致（无偏离）的采购订单，由平台在生成时**同事务自动核准生效（Auto-approve）**，直接将预算预占结转为正式承诺占用（多退少补释放差额），无需采购员重复提交全套订单审批，杜绝审批冗余；订单直接进入待下达状态。
- **协议下单与偏离审批**：按框架协议下单的释放订单（Release PO），或由定标派生但采购员补充修改了交货期拆批、运费/附加条款等实质内容的订单，仍须提交人工订单审批（或针对偏离项的多级增量审批），审批通过后方可登记生效与结转预算。

### 4.2 多公司、多币种与范围控制

1. 公司限定权限、供应商准入、审批规则、预算与结算范围；禁止引用其他公司的发票、预算和协议额度。
2. 交易币种、预算币种和公司本位币分别表达；汇率记录方向、来源、日期和精度。比价汇率与承诺入账汇率分开，后续更新汇率不得改写历史承诺。
3. 金额按币种的小数位规则舍入，不能固定所有币种两位。不同币种先转换再合计；原币、换算金额及舍入差额都可追溯。
4. 同一承诺明细支持按预算项拆分金额；分配合计必须等于该明细的预算口径金额。
5. 默认管理口径为申请审批通过建立预占、订单批准（含定标自动核准）或直接履约合同审批通过转为正式承诺占用（多退少补释放估算差额）、收货或非实物验收转执行、关闭未履约义务或取消申请释放；各公司采用不同执行时点时须绑定规则版本。发票与付款不重复消耗已执行的采购预算。
6. 发票和付款引用有效的承诺及履约依据；汇兑差额作为独立财务差异，不能反向重写采购单价。本轮普通付款路径先限制支付币种与应付币种一致，跨币种结算需补充差额分录及清算规则后启用。

### 4.3 寻源合规、密封开标与准入控制

1. **密封递交与盲收原则**：在征集文件设定的截止时间（Deadline）到达前，所有供应商递交的报价文件或投标文件处于绝对加密密封状态。经办采购员执行“盲收登记”，仅记录送达时间、主体及文件哈希/封条凭据（`sealed_hash`），系统单据状态为 `SEALED`。严禁在截标前拆封、查看或向业务接口暴露价格与商务细节，杜绝泄标、串标及暗箱压价风险。
2. **截标封存与集中开标解密**：到达截止时刻，系统自动关闭递交窗口，单据转为 `CLOSED`。截标后由开标见证人/监标人核对密封凭据完整性，触发“集中开标解密事务”，原子解析并写入明细报价与总金额，状态转为 `UNSEALED / RECORDED`，同时生成不可篡改的《开标记录表》（Opening Register 快照），随后方可进入比价与专家评审。
3. **潜在供应商与准入时效控制**：
   - 目录内日常协议采购必须为已准入启用的合格供应商（`APPROVED` & `ACTIVE`）；
   - RFQ、RFP 与公开招标寻源允许完成基础主体信息建档的潜在供应商（`PROSPECT`）被邀请或参与竞价，以扩大竞争范围；
   - 实行“定标后/签单前正式准入（Post-qualification）”：综合评审入围并拟定标授予的潜在供应商，必须在**采购订单正式核准生效（或直接履约合同前置审批锁定）前**通过正式准入审批；未准入供应商禁止生效合同或下达正式订单。

### 4.4 变更控制

变更单针对一个合同或订单的确定版本。草稿编辑可直接修改；已生效文件改变范围、价格、日期或付款条件必须提交变更审批，需要双方确认的条款还应保留确认凭证。

批准变更时锁定当前承诺版本和相关预算：增加部分补占预算，减少部分仅释放未履约占用，已经收货、验收、开票或实付的部分不得通过改小原单据抹除。对已发生业务的纠错、退货、贷项或退款使用独立凭证。

协议变更只影响批准后新下达的订单；已有订单保留原协议版本，要改已有订单须另行办理其变更。两个针对同一基准版本的变更不能都直接生效，后批准者须重新评估差异。

| 对象 | 主状态 | 关键约束 |
| ---- | ------ | -------- |
| 申请、方式例外、授予 | 草稿 → 审批中 → 已批准；另有退回、拒绝、取消 | 申请批准冻结版本并建立预算预占；取消或终止释放预占；来源已被使用时不能直接取消 |
| 采购任务 | 待分配 → 已分配 → 处理中 → 已完成；另有取消 | 改派留历史；完成只代表委派工作结束 |
| 供应商准入 | 潜在(PROSPECT)/草稿 → 审批中 → 已准入(APPROVED)；另有退回、拒绝、取消 | 潜在供应商可参与寻源；定标后下达订单或签约生效前必须正式准入且启用 |
| 征集文件 | 草稿 → 审批中 → 已批准 → 征集中(OPEN) → 已截止(CLOSED) → 已开标(UNSEALED) → 已授予；另有退回、拒绝、取消 | 截标前密封递交；截标后集中解密并记录开标事实；发布版本冻结 |
| 响应 | 已递交密封(SEALED) → 已开标(RECORDED) → 有效或无效；另有已撤回、已替代 | 截标前加密封存；开标事务解密生成开标记录；版本不可覆盖 |
| 合同 | 草稿 → 审批中 → 已批准 → 待生效 → 生效 → 关闭；另有退回、拒绝、终止 | 签署事实单独记录；直接履约合同在审批通过时签前锁定正式承诺占用；审批时必须校验供应商 APPROVED/ACTIVE；已批准版本生成受控待签文件；签署登记后激活生效，不因预算不足拒绝生效 |
| 订单 | 草稿 → 审批中 → 已批准 → 已下达 → 关闭；另有退回、拒绝、取消 | 审批时必须校验供应商 APPROVED/ACTIVE；定标无偏离且合格供应商派生订单由平台自动核准为已批准并结转承诺占用；潜在供应商或有偏离订单经准入及审批后结转；下达保留送达依据；交付与结算另设派生状态 |
| 变更单 | 草稿 → 审批中 → 已批准 → 已生效；另有退回、拒绝、取消 | 已批准但待双方确认时不改原义务；应用变更只执行一次 |
| 非实物验收 | 草稿 → 待确认 → 已确认；另有退回、拒绝、已冲销 | 专业验收与财务复核分开；确认后修改走纠错 |
| 发票 | 草稿 → 复核中 → 已确认；另有退回、拒绝、作废 | 应付只计有效已确认票据；待复核分配也预留履约可开票额 |
| 付款申请 | 草稿 → 审批中 → 已批准 → 已结清；另有退回、拒绝、取消 | 提交时预留可申请额；批准生成授权，已实付部分不可撤销 |
| 付款授权 | 有效 → 已用尽；另有剩余额已撤销 | 已用金额从付款登记派生；授权本身不能标记已实付 |
| 付款登记 | 草稿 → 复核中 → 已确认；另有退回、拒绝、已冲销 | 一笔实付唯一外部参考；冲销登记不等于银行退款 |

审批主体和权限不能因页面由助手打开而改变。助手可解释、比对、准备草稿及按委托提交；审批、签署、正式验收、库存过账、支付授权和财务复核均由授权人员完成。

## 6. 配套业务动作

下列动作按条件触发，不强行串入每次采购主线。每行仍由一个角色执行一个动作。

| 编号 | 触发情形 | 执行角色 | 动作 | 结果或下一步 |
| ---- | -------- | -------- | ---- | ------------ |
| S01 | 采购员离岗或分工调整 | 采购负责人 | 改派采购任务 | 保留原负责人、接任人和原因，通知由平台生成 |
| S02 | 供应商尚未准入 | 供应商管理员 | 提交公司准入申请 | 关联资质及审查依据 |
| S03 | 准入待审核 | 准入审批人 | 审批供应商准入 | 通过后才能参与该公司正式采购 |
| S04 | 范围或条款不清 | 供应商 | 提出澄清请求 | 首期通过线下渠道提出 |
| S05 | 收到澄清问题 | 采购员 | 登记澄清请求 | 关联对应征集版本 |
| S06 | 澄清待答复 | 采购员 | 发布澄清答复 | 按同等信息规则发送相关受邀方，保留记录 |
| S07 | 澄清改变实质范围 | 采购员 | 提交征集修订 | 重新审批、明确延期或新轮次，通知受影响供应商 |
| S08 | 需要更新响应 | 供应商 | 提交新版响应 | 旧文件保留，新响应仍按截止规则判断 |
| S09 | 收到新版响应 | 采购员 | 登记响应版本 | 不覆盖已用于评审的历史版本 |
| S10 | 响应不足或均不合格 | 采购员 | 提交重新征集申请 | 保留失败轮次；批准后重新发布 |
| S11 | 需要单一来源或其他例外 | 采购员 | 提交采购方式例外 | 附必要理由，不豁免预算和正式采购审批 |
| S12 | 例外待审批 | 采购方式审批人 | 审批采购方式例外 | 确定允许的范围及有效期 |
| S13 | 需求或价格变化 | 采购员 | 提交采购变更单 | 关联原合同或订单版本及增减差额 |
| S14 | 变更待审批 | 变更审批人 | 提交变更审批决定 | 根据范围和金额走相应节点 |
| S15 | 变更需双方确认 | 合同签署人 | 确认变更条款 | 保留双方确认凭证 |
| S16 | 变更生效条件齐全 | 平台 | 应用已批准变更 | 版本、预算和剩余义务原子更新 |
| S17 | 分批交付延期 | 采购员 | 登记催交结果 | 实际承诺日期变化需按变更规则处理 |
| S18 | 验收不通过 | 业务验收人 | 记录验收差异 | 不确认不合格范围的预算执行或应付依据 |
| S19 | 需要整改 | 采购员 | 发起整改要求 | 保留责任、截止日和整改证据，之后重新验收 |
| S20 | 不再采购剩余量 | 采购员 | 提交余量关闭申请 | 只关闭尚未履约范围 |
| S21 | 余量关闭待审批 | 订单审批人 | 审批余量关闭 | 通过后平台释放相应占用 |
| S22 | 发票与履约不符 | 财务登记人 | 登记发票差异 | 阻止确认，退回相关负责人核实 |
| S23 | 尚未实付的授权不再需要 | 付款申请人 | 提交付款授权撤销申请 | 仅申请释放未付余额；有待复核实付时须先核实 |
| S24 | 撤销待审批 | 付款审批人 | 审批剩余授权撤销 | 不删除已有真实付款记录 |
| S25 | 已付款退货、预付款或超付 | 财务人员 | 登记特殊结算异常 | 保留真实事实；对应结算能力未实现前不得伪造闭环 |
| S26 | 合同即将到期 | 平台 | 生成合同到期待办 | 不自动续签或自动创建新承诺 |
| S27 | 需要继续合作 | 采购员 | 提交续购需求 | 重新判断采购方式和预算，不默认沿用原审批 |

退货、库存冲销、预算调整、汇率缺失和付款录入纠错等基础分支继续见[平台 README](../README.md#常见异常与分支流程)。有付款或发票关联的退货须先明确财务处理路径，不能靠删除记录恢复额度。

## 7. 付款额度与一致性

本轮普通支付采用“已确认应付 → 付款申请 → 审批授权 → 实付登记 → 复核”的路径。预付、进度款无票支付、保留款、贷项抵扣和跨币种净额结算属于独立结算规则，不用普通发票余额算法直接套用。

同一张发票的可新申请付款额 = 已确认应付 − 已确认有效实付 − 尚未结清的申请占用。申请占用包含审批中的申请以及获批授权尚未转为确认实付的余额；该授权下的待复核实付已经包含在申请占用内，不能再扣一次。

例如应付 100，付款申请获批 60 后，可新申请 40；登记并确认该授权下的实付 20 后，实付为 20，授权未结清占用为 40，可新申请仍为 40。

提交付款申请锁定应付来源并建立占用；拒绝、退回或撤回释放未实付占用。付款登记提交锁定授权余额，待复核加已确认实付不能超过授权。复核将相应占用转为实付，失败全部回滚。部分支付后撤销剩余额须先检查无未决实付；已发生异常支付保留原始凭证并进入核实。

合同/订单生效、应用变更、收货或验收确认、发票复核、付款申请占用及实付复核，都必须在同一业务库事务内完成各自的校验和记账。API 采用明确动作、内容版本和幂等键，不提供任意改状态的接口。

## 8. 工程落地与验收

目标范围已包含多公司、多币种和实物、服务、许可、订阅。工程按业务切片交付，不把未实现能力通过空按钮或文本字段假装支持。

| 切片 | 应交付能力 | 必须验证的业务结果 |
| ---- | ---------- | ------------------ |
| P0 公共基础 | 公司与权限、币种及汇率、分类、预算分配、版本和审批 | 不可跨公司引用；历史汇率不随新配置变化 |
| P1 RFQ 闭环 | 申请、审批、分配、需求核实、方式、询价、报价、评审授予、订单、实物及非实物履约、发票、付款申请与实付 | 两种履约均可独立闭环；付款授权与实付分开；重复提交不重复占用 |
| P2 合同与协议 | 框架及服务协议、直接履约合同、协议下单、变更与到期提醒 | 同一义务不重复占预算；并发下单不超协议额度；旧订单不被协议变更覆盖 |
| P3 RFP 与招标 | 方案响应、评审标准、澄清补遗、响应封存、授予与合同衔接 | 评审引用确定版本；修改范围重新发布；缺少有效响应不能强制授予 |
| P4 复杂结算与运营 | 按实际公司制度补预付、保留款、贷项退款、跨币种结算，完善绩效与助手工具 | 真实差异可追溯，自动化只调用已实现且授权的业务动作 |

数据库实施需先重构采购来源与履约明细，随后同步预算、发票、付款外键和接口。不能只新增合同页面，继续要求所有收货、验收及发票必填旧订单行。具体字段缺口已在数据库文档开头列出；完成字段设计、迁移和真实数据库验证后，才可以宣称对应切片实现。
